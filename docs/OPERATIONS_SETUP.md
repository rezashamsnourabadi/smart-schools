# راه‌اندازی تکمیل عملیات پلتفرم

آخرین تطبیق: **2026-10-30**. [فهرست مستندات](README.md).

## اجرای محلی

پس از بالا بودن PostgreSQL، Redis و MinIO، `npm run db:migrate` و یک بار `npm run storage:init` اجرا شوند. API و فرانت‌اند با فرمان توسعه فعلی اجرا می‌شوند؛ `npm run worker` نیز باید در فرایند جدا روشن باشد. اعلان عمومی زنگوله، صف ارسال و پاک‌سازی آمار به worker وابسته‌اند. API و worker باید به همان پایگاه داده/Redis و تنظیمات کانال متصل باشند؛ راه‌اندازی محلی قبلی گواه زنده‌بودن دائمی فرایند نیست. worker در هر نوبت حداکثر پنج دسته ۲۰۰ عضوی اعلان و یک دسته هزار رویدادی پاک‌سازی پردازش می‌کند؛ آزمون بار اجرا نمی‌کند.

در تولید، مهاجرت پیش از نسخه جدید API/worker اجرا شود. Migrationهای 014 تا 016 افزایشی و مربوط به پیشنهاد/نظرسنجی، ارزشیابی دبیران و اعلان پاسخ پیشنهادها هستند. `compose.production.yaml` متغیرهای جدید بله را به API و worker می‌رساند. پورت داخلی برنامه همچنان 3000 است.

## اتصال بله

پارامترها در محیط خصوصی سرور:

- `BALE_BOT_TOKEN`: توکن ربات ساخته‌شده برای همین سامانه.
- `BALE_BOT_USERNAME`: نام کاربری ربات بدون @.
- `BALE_WEBHOOK_SECRET`: کلید تصادفی مستقل با ۳۲ تا ۱۲۸ نویسه لاتین، عدد، خط تیره یا زیرخط. از رمز یا توکن ربات استفاده نشود.
- `APP_ORIGIN`: مبدأ عمومی HTTPS سامانه پشت پراکسی TLS.

وب‌هوک باید توسط مسئول استقرار برای همین ربات به آدرس زیر ثبت شود:

```text
https://YOUR_PUBLIC_HOST/api/v1/integrations/bale/webhook?secret=YOUR_PRIVATE_WEBHOOK_SECRET
```

نمونه PowerShell زیر **راهنماست و در توسعه خودکار اجرا نشده است**؛ ثبت وب‌هوک، دریافت آپدیت همان ربات را به این سامانه منتقل می‌کند:

```powershell
$baleWebhookUrl = "$env:APP_ORIGIN/api/v1/integrations/bale/webhook?secret=$env:BALE_WEBHOOK_SECRET"
Invoke-RestMethod -Method Post -Uri "https://tapi.bale.ai/bot$env:BALE_BOT_TOKEN/setWebhook" -Body @{ url = $baleWebhookUrl }
```

در پراکسی نیز query string این مسیر نباید ثبت شود. لاگر API query را ثبت نمی‌کند. ارسال به بله و ثبت وب‌هوک از طریق HTTPS است؛ مستندات رسمی درگاه عمومی وب‌هوک را 443 یا 88 معرفی می‌کنند. پراکسی می‌تواند این ورودی را به برنامه داخلی روی 3000 برساند. منبع قرارداد درخواست، پیوند شروع و وب‌هوک: [مستندات رسمی بازوی بله](https://docs.bale.ai/).

کاربر از زنگوله ← «تنظیم دریافت در بله» کد ده‌دقیقه‌ای می‌سازد و پیوند ربات را باز می‌کند، یا فرمان `/start CODE` را در گفت‌وگوی خصوصی همان ربات می‌فرستد. فقط آپدیت دارای secret درست و فرستنده برابر گفت‌وگوی خصوصی می‌تواند کد را مصرف کند. شناسه بله پرونده، اتصال تأییدشده حساب محسوب نمی‌شود. قطع اتصال، ارسال‌های مستقیم صف‌شده به ارتباط قبلی را نامعتبر می‌کند.

نبود پیکربندی، مسیر اتصال/ارسال را صریحاً ناموجود می‌کند. کد و صف داخلی با شبیه‌سازی آزموده شده‌اند؛ تحویل واقعی باید پس از تأمین ربات، مبدأ عمومی و اعتبارنامه با حساب آزمایشی خود مسئول استقرار بررسی شود. سرویس SMS نیز همچنان به قرارداد webhook موجود و اعتبارنامه ارائه‌دهنده وابسته است.

## رفتار قابلیت‌ها

- پیوست تیکت پس از ثبت اولیه و در گفت‌وگوی تیکت قابل افزودن است؛ ده فایل خصوصی، هرکدام دو مگابایت. تیکت بسته پیوست جدید نمی‌پذیرد. رسیدگی به هر مدیر پلتفرم فعال قابل ارجاع است و ارجاع در زنگوله او می‌نشیند.
- گزینه زنگوله اطلاعیه فقط هنگام انتشار جدید است؛ ویرایش، سنجاق و تلاش مجدد همان درخواست، ارسال گروهی تازه ایجاد نمی‌کنند. حساب‌ها و عضویت‌ها هنگام ارسال مجدداً کنترل می‌شوند؛ عضویت جدید پس از انتشار به مخاطبان قبلی اضافه نمی‌شود. تغییر مخاطب یا بایگانی، ادامه صف قبلی را لغو می‌کند؛ پیام‌های دریافت‌شده قبلی حذف نمی‌شوند.
- پیام دبیر به انتخاب دقیق کلاس/درس و سال جاری فعال وابسته است. گیرنده فقط دانش‌آموز/ولی دارای ثبت‌نام فعال همان کلاس است. چند کلاس و چند درس، ترکیب‌های دلخواه تازه مجاز نمی‌سازند.
- آمار ← «نگهداری داده خام آمار»: پیش‌فرض ۱۸۰ روز، بازه ۹۰ تا ۷۳۰، قابلیت توقف پاک‌سازی، کنترل نسخه و ممیزی. رویداد قدیمی‌تر حذف می‌شود؛ بایگانی دائمی یا بازگردانی داده حذف‌شده در این سیاست وجود ندارد. گزارش رابط حداکثر نود روز است و شمارنده قدیمی تبلیغ با پاک‌سازی رویدادها پاک نمی‌شود.

## بررسی محدود

`npm run lint_applet`، `npm run compile_applet` و فقط فایل کوتاه `server/tests/school-access-support.test.ts` بررسی‌های این مرحله‌اند. فایل و وب‌هوک در آزمون شبیه‌سازی می‌شوند و پیام خارجی ارسال نمی‌شود. تست مرورگر و بار اجرا نشده است.
