# حافظه فنی و تصمیم‌های پروژه

## تصمیم‌های جدید

- ADR-018: بازطراحی مرحله‌ای از دانش‌آموز شروع شد. چهار نمای رابط و چهار دسترسی پرونده جای دیوار کارت‌های طولانی را گرفتند. برنامه بر اساس روز انتخاب می‌شود؛ آزمون‌ها، اطلاعیه‌ها، تمرین و بانک سؤال، پاسخ متنی/پیوست و بازخورد دبیر حفظ شده‌اند. پیش‌نویس‌های تکلیف به شناسه تکلیف وابسته‌اند تا متن دو تکلیف با هم مخلوط نشود. وضعیت ارسال تا پاسخ موفق سرور تأیید نمی‌شود.
- ADR-019: پرونده مشترک با ناوبری چندردیفی، دکمه‌های لمسی و بدنه با اسکرول مستقل بازطراحی شد؛ تب‌ها افقی اسکرول نمی‌شوند. نام و مقادیر طولانی می‌شکنند و ورودی‌ها عرض پنجره را بزرگ نمی‌کنند. هدر، بستن و چاپ در دسترس‌اند و اسکرول صفحه پشت پنجره قفل می‌شود. حرکت کوتاه Motion ترجیح کاهش حرکت را رعایت می‌کند. API، مدل داده و مجوزها تغییر نکرده‌اند.
- بررسی این مرحله بنا به خواسته کاربر فقط TypeScript و build است؛ آزمون بار، مجموعه آزمون‌ها و بررسی مرورگر اجرا نمی‌شوند. بازبینی ظاهری روی گوشی با کاربر است. تغییرات قبل از این بازطراحی در کامیت 6009c0e روی main پوش شده‌اند؛ بازطراحی جدید برای بازبینی جدا نگه داشته می‌شود.

- ADR-014: ورود گوشی با IP لپ‌تاپ به‌علت تطبیق ثابت Origin با localhost رد می‌شد. اعتبارسنجی مبدأ اکنون فقط در development آدرس‌های واقعی کارت شبکه میزبان روی HTTP:3000 را نیز می‌پذیرد. تولید/test همچنان APP_ORIGIN دقیق دارند. به هدر Host یا صرفاً خصوصی‌بودن یک IP اعتماد نمی‌شود؛ CSRF غیرفعال نشده است.

- ADR-013: صفحه اصلی به معرفی عمومی دانا اختصاص یافت و نقطه ورود به `/login` منتقل شد. LandingPage مستقل از API است؛ بارگذاری AuthShell و پنل‌ها تا ورود به مسیر احراز هویت عقب می‌افتد. نمونه میز کار در لندینگ، تصویرسازی نمایشی بدون داده شخصی یا آمار زنده است. پرسش‌های متداول با details/summary بومی و بدون کتابخانه جدید کار می‌کنند. حرکت ورودی کوتاه، ترجیح کاهش حرکت را رعایت می‌کند؛ مسیرهای ابزارهای بررسی ورود نیز با `/login` هماهنگ شدند.

- ADR-005: منبع حقیقت از Context/localStorage به PostgreSQL منتقل شد. نمونه قدیمی فقط fixture آزمون در tests/fixtures است و در برنامه تولیدی import نمی‌شود.
- ADR-006: هویت کاربر، عضویت مدرسه و هویت دانش‌آموز جدا هستند. انتخابگر نقش مجوز ایجاد نمی‌کند؛ مدیر منطقه impersonation عمومی ندارد.
- ADR-007: envelope رابطه‌ای سال‌دار با payloadهای JSONB معتبر انتخاب شد تا UI فعلی حفظ شود. امنیت و روابط مهم به داده داخل JSON یا شناسه ارسالی مرورگر واگذار نشده‌اند.
- ADR-008: نشست قابل ابطال در سرور به‌جای توکن در web storage؛ رمز Argon2id، کد پیامکی و CSRF. کد توسعه فقط در فایل ignored محلی است؛ Vite اجازه ارائه .local و فایل‌های سرور را ندارد.
- ADR-009: نسخه رکورد برای ویرایش و Idempotency-Key برای درخواست حساس. ثبت مالی قفل ردیف دارد؛ اعلان از outbox همان تراکنش منتشر می‌شود.
- ADR-010: هر درخواست یک تراکنش/اتصال دارد. آزمون بار، خطر اتصال تو‌در‌تو و هزینه round-tripهای زائد را آشکار کرد؛ آزمون هم‌زمانی بیش از اندازه pool اضافه شد.
- ADR-011: ورود، dashboard و مدال‌ها جدا بارگذاری می‌شوند. داده خصوصی فقط در حافظه مرورگر است و با تغییر حساب/عضویت پاک می‌شود.

## تصمیم بهینه‌سازی سبک

- ADR-012: بهینه‌سازی محدود درخواست‌ها بدون بازنویسی Context یا دیتابیس: preload تکلیف/آزمون دبیر حذف، کلید مالی محدود به students، و invalidation عملیات مستقل محدود به منابع وابسته همان عضویت/سال شد. تحویل تکلیف دو فهرست homework و homeworkSubmissions را تازه می‌کند. پاسخ موفق ثبت از پایان refetch پس‌زمینه مستقل است؛ خطای refetch نباید شکست نوشتن گزارش شود. سایر عملیات، به‌ویژه مالی/حضور/دانش‌آموز/سال، رفتار قبلی را دارند. بررسی این مرحله فقط lint_applet و compile_applet است؛ تست مرورگر، آزمون بار یا سنجش سرعت اجرا نمی‌شود.

## قواعد نگهداری

پورت عمومی 3000 و RTL حفظ شود. داده واقعی به mock fallback نکند. در سال غیرجاری عملیات نوشتن ممنوع است. تغییر شماره پرونده به‌معنی تغییر شماره بازیابی حساب نیست. مرجع روابط والد/دانش‌آموز و نقش، سرور است. ledger از مرورگر دریافت نمی‌شود.

DB migration با حساب owner و اجرای API با school_app انجام می‌شود. RLS نباید برای رفع خطای محیط خاموش شود. index مستقل روی کلیدهای خارجی لازم است؛ تست/پاک‌سازی دسته‌ای نباید همه مدارس را اسکن کند.

## نقاط ورود

server/index.ts: اجرای API و فایل‌های build. server/app.ts: hooks، امنیت، قرارداد و خطا. resources/commands: خواندن و عملیات دامنه. auth: نشست و کد. worker: outbox و ارسال. infra/backup.ts: پشتیبان AES-GCM و بازیابی در مقصد تازه.

src/auth: ورود، bootstrap سبک و مدیریت نشست. src/context/AppContext.tsx: adapter مؤلفه‌های فعلی و state رابط. src/api/hooks.ts: داده جلسه حضور و سابقه اختصاصی دانش‌آموز. فرم‌ها تا پاسخ موفق سرور باز می‌مانند.

## آزمون‌ها و کار باقی‌مانده

آزمون‌های PostgreSQL و S3 واقعی، هفت بررسی قدیمی دامنه و آزمون مرورگر شش نقش اضافه شده‌اند. build لینوکس بررسی می‌شود. نتیجه دقیق ظرفیت و بودجه عملکرد، صرفاً از گزارش VALIDATION.md خوانده شود؛ گذشتن lint/build تأیید ظرفیت نیست.

فعال‌سازی سرویس پیامک، بله و درگاه، انتخاب میزبان و فعال‌سازی timer پشتیبان به اطلاعات عملیاتی کاربر وابسته‌اند. بدون تنظیم سرویس، ارسال موفق جعل نمی‌شود. آرشیو سالانه برای داده جدید مستقل است؛ نسبت‌دادن داده محلی قدیمی به سال نیازمند مهاجرت جداست.

اسناد اصلاحات فرانت‌اند پیشین در docs/archive نگه داشته شده‌اند؛ محدودیت فرمول رسمی معدل همچنان با ورود دستی کارنامه مدیریت می‌شود.


## تصمیم اجرایی 2026-10-27

آزمون بار بنا به درخواست کاربر متوقف شد و ادامه نمی‌یابد؛ ظرفیت هدف، ظرفیت تأییدشده نیست. راهنمای اجرا در DEPLOYMENT.md و نتایج و محدودیت‌ها در VALIDATION.md ثبت شده‌اند. CI بررسی ایستا، build و آزمون عملکردی دارد؛ آزمون بار در CI اجرا نمی‌شود.


## تصمیم‌های 2026-10-28

- ADR-015: بنا به تغییر خواسته محصول، الزام رمز به‌همراه SMS مدیر حذف شد؛ همه نقش‌ها دو روش مستقل ورود دارند. privileged برای زمان نشست حساب حساس و auth_method برای روش ورود هستند؛ این دو مفهوم دیگر با نام MFA مخلوط نیستند. انتقال شماره بازیابی و بازیابی رمز همچنان مسیرهای امنیتی مستقل خود را دارند.
- ADR-016: مسیر نقش با history.replaceState به `/dashboard/<role>` تغییر می‌کند؛ انتخاب عضویت و کش خصوصی همچنان از AuthProvider کنترل می‌شوند. GET مستقیم، تازه‌سازی، خروج و انقضا باید با این مسیرها سازگار بمانند. خروج بدنه JSON خالی می‌فرستد تا با قرارداد API مطابقت داشته باشد.
- ADR-017: linkUrl برای تبلیغات اضافه شد؛ مدیر می‌تواند بنر موجود را ویرایش کند. کلیک کارت/دکمه یک مقصد را در تب جدید باز می‌کند و آمار، رفتن به مقصد را مسدود نمی‌کند. خطای شمارش کلیک toast ثبت موفق/ناموفق فرم ایجاد نمی‌کند. کدهای تست فعلی با تغییر روش ورود و مسیرها هماهنگ شده‌اند.


- ADR-020: پس از بازطراحی دانش‌آموز، هدر و ابزارهای مشترک آن (اعلان، حساب، مدرسه/سال، پروفایل، امنیت، راهنما و مدیریت حساب) برای همه نقش‌ها هماهنگ شدند. منوی خروج داخل حساب قرار دارد؛ selectorهای گردش‌کار مرورگر با محل جدید دکمه‌ها هماهنگ شده‌اند، اما این مجموعه در این مرحله اجرا نمی‌شود.
- ADR-021: بازطراحی بانک سؤال، جستجوی سروری عنوان را از فیلترهای محلی همین صفحه مشخص می‌کند تا دو جستجوی نامشخص کنار هم نباشند. حالت‌های تستی/تشریحی/کوتاه‌پاسخ، کلید و راهنما، کپی و ثبت سؤال برای نقش مجاز حفظ شده‌اند؛ متن قدیمی ذخیره در مرورگر و ادعای تأیید آموزشی از رابط حذف شد.
- ADR-022: تبلیغ دانش‌آموز قبل از محتوای تمام نماها ثابت شد. دانا پلاس به‌صورت معرفی مستقل از مدرسه با نشان به‌زودی و میان‌بر صفحه اضافه شد؛ هیچ ظرفیت عملیاتی دوره یا اشتراک ادعا نمی‌شود. بررسی این مرحله فقط lint_applet و compile_applet است؛ بازبینی مرورگر با کاربر است.


- ADR-023: صفحه خالی پس از ورود با خطای Authentication required در AppProvider بازتولید شد. Context و useAuth از فایل کامپوننت AuthProvider به AuthContext.ts منتقل و واردکردن همه مصرف‌کننده‌ها یکسان شد. پس از بارگذاری کامل، داشبورد دانش‌آموز و مسیر آن نمایش داده شدند؛ lint_applet و compile_applet موفق بودند.


- ADR-024: برای کاهش مزاحمت بصری، کارت تیره دانا پلاس و میان‌بر بالای صفحه با یک معرفی جمع‌شونده روشن در انتهای خانه جایگزین شدند. خوشامد، میان‌برهای شخصی و آیکون بخش‌ها رنگ و عمق ملایم گرفتند؛ همه امکانات مدرسه حفظ شدند. بررسی این تغییر محدود به lint_applet و compile_applet است.
